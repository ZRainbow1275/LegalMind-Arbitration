# 06｜运维后台（身份/权限/日志/策略/对接配置）：独立入口 + 强制 MFA + 最小权限

## 0. 目标
- 独立运维后台：管理身份与权限、审计日志、系统策略、外部对接配置、队列与存储状态
- 安全基线：强制 MFA（TOTP/硬件令牌策略）、最小权限、关键操作二次确认与留痕

## 1. 运维后台模块（建议）
1) 身份与组织
   - 用户、机构、从属关系、实名/资质状态（律师/仲裁员/公证/法院）
2) 角色与权限
   - 平台角色（PlatformRole）
   - 案件角色（CaseRole）
   - 权限点（Permission）与策略（Policy/ABAC）
3) 审计与留痕
   - 安全审计（登录、权限变更、敏感访问）
   - 业务事件（CaseEvent）检索与导出
4) 外部对接配置
   - OIDC/IdP 配置（realm、client、JWKS）
   - 公安/法院/公证（接口地址、证书、验签、公钥轮换）
5) 基础设施与队列
   - Redis/队列堆积、失败重试、死信队列
   - MinIO bucket/生命周期/访问策略

## 2. 与现状代码的差距提示
- `dev/src/app/api/admin/*` 已加固为仅 `OPS_ADMIN`（CSRF + 角色校验）；仍缺少运维后台的“用户/角色/审计查询”操作界面与配套 API（执行阶段补齐）。
- 当前 MFA 管理器为“6 位码 + Redis 存储”形式，占位；运维后台必须升级为 TOTP 等可审计方案。
