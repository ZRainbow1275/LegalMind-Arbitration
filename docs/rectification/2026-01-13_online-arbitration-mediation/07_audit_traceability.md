# 07｜全过程留痕与可取证：审计日志 + 业务事件 + 证据链校验

## 0. 目标
让平台满足“全法律过程线上处理、全过程留痕”，并支持：
- 事后复盘：还原谁在何时做了什么
- 争议取证：证明证据/笔录/录制产物未被篡改
- 合规导出：按案件/时间/角色导出日志与事件

## 1. 三条线并行（缺一不可）
1) `AuditLog`（安全审计）：登录、权限变更、敏感访问、异常与风控事件
2) `CaseEvent`（业务事件）：案件推进、邀请/合意、会议室阶段、庭审关键动作
3) `EvidenceChain`（证据链）：文件/笔录/录制/协议等产物的哈希与链式校验

## 2. 关键写操作（必须产生日志与事件）
- 发出邀请/撤回邀请/接受/拒绝/披露提交
- 双方合意确认/撤回
- 任命生效/解除任命
- 庭审开始/结束/录制开始/结束/证据展示切换
- 调解阶段推进/协议草案生成/签署完成
- 文件上传/下载/查看（尤其是证据）

## 3. 导出与校验（D5A）
- 导出内容：
  - 案件事件流水（含 hash）
  - 证据清单与每个版本的 sha256
  - 关键确认的签名/时间戳任务结果
- 校验工具（执行阶段提供）：
  - 给定导出包，验证 hash 链一致性与缺失项

## 4. 统一追踪标识
- `traceId`：每次请求贯穿 API、队列任务与审计
- `caseId/hearingId/mediationId`：强制作为事件与审计的关联键
